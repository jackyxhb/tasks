# Meeting Transcription and Extraction JSON Contract

## Purpose

This document defines the structured JSON contract for meeting transcription, summarization, and extraction in version 1 of the personal field work agent app.

The contract is designed to support:

- audio transcription
- cleaned transcript generation
- meeting summary generation
- minutes extraction
- decision extraction
- task candidate extraction
- project linking candidates
- confidence-aware review

The app should validate this JSON locally before saving any derived records.

## Design Rules

- raw audio remains the source evidence
- transcript output must not overwrite raw source data
- all extracted fields should be reviewable
- low-confidence items must remain candidates, not final records
- output must be valid JSON only

## Top-Level Response Shape

```json
{
  "schema_version": "v1",
  "request_id": "uuid",
  "provider": {
    "name": "string",
    "model": "string"
  },
  "transcription": {
    "language_mode": "bilingual_en_zh",
    "detected_languages": ["en", "zh"],
    "raw_transcript": "string",
    "cleaned_transcript": "string",
    "speaker_segments": []
  },
  "meeting": {
    "title": "string",
    "meeting_datetime_text": "string",
    "meeting_location_text": "string",
    "summary": "string",
    "minutes_items": [],
    "decision_items": [],
    "open_questions": []
  },
  "project_candidates": [],
  "people_mentions": [],
  "task_candidates": [],
  "confidence": {
    "overall": 0.0,
    "transcript": 0.0,
    "meeting_summary": 0.0,
    "project_linking": 0.0,
    "task_extraction": 0.0
  },
  "warnings": []
}
```

## Field Definitions

### `schema_version`

- string
- required
- current value: `v1`

### `request_id`

- string
- required
- generated by caller for traceability

### `provider`

Fields:

- `name`
- `model`

Both required for auditability.

## `transcription`

### Shape

```json
{
  "language_mode": "bilingual_en_zh",
  "detected_languages": ["en", "zh"],
  "raw_transcript": "full transcript text",
  "cleaned_transcript": "lightly cleaned transcript text",
  "speaker_segments": [
    {
      "speaker_label": "Speaker 1",
      "start_ms": 0,
      "end_ms": 4200,
      "text": "string",
      "confidence": 0.84
    }
  ]
}
```

Rules:

- `raw_transcript` is required unless transcription failed completely
- `cleaned_transcript` is optional but recommended
- `speaker_segments` may be empty if diarization is unavailable

## `meeting`

### Shape

```json
{
  "title": "Coordination Meeting for Pompallier Ponsonby",
  "meeting_datetime_text": "2026-03-09 07:30 AM",
  "meeting_location_text": "302 Ponsonby Road, Ponsonby, Auckland 1011",
  "summary": "Short meeting summary.",
  "minutes_items": [
    {
      "sequence": 1,
      "text": "Joel confirmed morning access to the site.",
      "confidence": 0.91,
      "source_snippet": "Joel said site access is ready this morning"
    }
  ],
  "decision_items": [
    {
      "sequence": 1,
      "text": "Proceed with on-site training for Lin Yong this morning.",
      "confidence": 0.89,
      "source_snippet": "Let Lin Yong do the training this morning"
    }
  ],
  "open_questions": [
    {
      "text": "Whether tuning support is needed after the training session.",
      "confidence": 0.58,
      "source_snippet": "maybe we still need tuning support later"
    }
  ]
}
```

Rules:

- `summary` should be short and factual
- `minutes_items` and `decision_items` should remain separate
- `source_snippet` is required for every extracted item

## `project_candidates`

### Shape

```json
[
  {
    "project_name": "Pompallier Ponsonby",
    "client_oem": "OTIS",
    "site_location": "302 Ponsonby Road, Ponsonby, Auckland 1011",
    "site_contact_name": "Joel",
    "site_contact_phone": "021 194 0200",
    "coordinator_name": "Jack Xiao",
    "project_manager_name": null,
    "match_type": "existing_or_new",
    "confidence": 0.94,
    "source_snippet": "Project Pompallier Ponsonby, Joel on site, OTIS job"
  }
]
```

Rules:

- `project_name` is required
- `confidence` is required
- `source_snippet` is required
- `match_type` allowed values:
  - `existing`
  - `new`
  - `existing_or_new`

## `people_mentions`

### Shape

```json
[
  {
    "name": "Lin Yong",
    "phone": "+64 29 777 7020",
    "role_hint": "worker",
    "confidence": 0.95,
    "source_snippet": "Worker Lin Yong plus six four two nine..."
  }
]
```

Rules:

- used for people matching and autofill
- does not create final people records automatically without local validation

## `task_candidates`

### Shape

```json
[
  {
    "candidate_id": "tc_001",
    "task_type": "installation",
    "task_title": "On-site training support for Lin Yong",
    "description": "Assist the technician with on-site training.",
    "project_name": "Pompallier Ponsonby",
    "worker_name": "Lin Yong",
    "worker_phone": "+64 29 777 7020",
    "coordinator_name": "Jack Xiao",
    "project_manager_name": null,
    "scheduled_date_text": "2026-03-09",
    "start_time_text": "7:30 AM",
    "duration_text": "morning, half day",
    "location_text": "302 Ponsonby Road, Ponsonby, Auckland 1011",
    "status_suggestion": "planned",
    "priority_suggestion": "medium",
    "confidence": 0.92,
    "ambiguities": [],
    "source_snippet": "Help our technician do on-site training this morning at 7:30"
  }
]
```

Rules:

- `candidate_id` required for UI tracking
- `task_type`, `task_title`, `project_name`, `confidence`, and `source_snippet` are required
- `ambiguities` must be an array even if empty

Allowed `task_type` values:

- `site survey`
- `installation`
- `tuning`
- `handover`
- `maintenance`
- `unknown`

## `confidence`

### Shape

```json
{
  "overall": 0.84,
  "transcript": 0.81,
  "meeting_summary": 0.88,
  "project_linking": 0.90,
  "task_extraction": 0.79
}
```

Rules:

- values must be numeric from `0.0` to `1.0`
- if a score cannot be estimated, use `null`

## `warnings`

### Shape

```json
[
  "Multiple projects may be referenced.",
  "Assignee name confidence is low for one task candidate."
]
```

Rules:

- plain-language warnings for the review UI

## Validation Rules

The app should reject or downgrade output if:

- JSON is invalid
- `schema_version` is missing
- required fields are absent from `task_candidates`
- confidence values are outside `0.0` to `1.0`
- arrays are returned as strings
- source snippets are missing for extracted items

The app should mark output as review-required if:

- multiple projects are detected
- inferred dates or times are used
- multiple workers are mentioned for one task candidate
- overall confidence is below threshold

## Recommended Thresholds

- `>= 0.85`: prefill aggressively, still review before finalize
- `0.65 - 0.84`: prefill with visible caution
- `< 0.65`: keep strongly marked as uncertain and avoid automatic linking
